# TRX 策略与运维说明

## 保留的功能

`freqtrade/strategy/trx_phase1` 是策略与账户逻辑，`freqtrade/rpc/api_server/api_trx.py` 提供专用 HTTP API。实盘、历史研究和虚拟执行共享决策引擎与批次账本。原 Freqtrade 原生策略适配器及其钱包已移除；实盘使用独立 `LiveService` / `LiveExecution` 流程。

- 策略：一分钟基础时钟、动态确认周期、价格位置、信号过期和执行前复核。
- 账本：Decimal 本金批次、实际手续费、部分成交、成本与已实现利润、独立留存利息。
- 研究：历史回放、参数对照、分段与跨期研究、逐笔诊断、风险和资金准备分析。
- 实盘：Bitget Classic 交易、理财申赎及到账核对、收入归属、账户增资与重启恢复。
- 运维：只读快照、历史曲线、独立告警与 Telegram 成交/生命周期通知、在线备份和资源采集。

## 策略和资金约束

一分钟收盘之后才形成决策；确认后的下一分钟才允许回放成交。UTC 边界定义长周期，波动率来自过去一分钟对数收益率。参数、周期和公共本金锚点在下一次评估之前冻结；一次确认最多形成一个待执行计划，执行前复核只能取消或缩减，不能临时创造信号。

公共本金锚点在第一次执行前固定，执行完成后按真实决策 VWAP 更新，本金归零后保留。利息、理财和币种兑换不改变锚点。实际成交及亏损如实记账；卖出分配只选择满足门槛的本金批次，优先较新的合格批次，留存利息不参加普通卖出。

账本 SQLite 使用版本校验和原子状态更新。重复成交与到账回执按其真实 ID 去重。未知金融请求不自动重发，应通过读取订单与回执核对。研究默认资金和收益率是假设，不构成实盘账户配置或已验证收益。

现金券奖励 `CASH_COUPON_ACTIVITY_USER_IN` 以原生账单 ID 和指纹核对，先单列为策略外奖励，不自动当作活期利息、交易返佣或新增本金。普通利息导入不会因此放行未知充值或手工交易。`account_movement_preview.preview` 可对暂停账户的已捕获流水做纯内存预览：逐项核对现货账单、成交与实际手续费、申购成功回执、当前活期持仓及账户理财汇总；账单的交易业务编号须先关联成交编号，再定位订单。人工操作按“外部资金先支出、兑换净到账按来源分配”的待确认口径展示，原策略资金的兑换与位置变动单列。预览没有写账、转账、申赎、交易或恢复入口，不重置本金、TRX成本或收益起点。

定额追加本金的只读筛选由 `contribution_preview.py` 和独立历史读取服务提供。`GET /api/v1/trx/live/contribution-preview` 明确选择 `coin=USDGO`、正数 `amount`（最多八位小数）及可选 `holding_id`；仅选择该理财持仓的策略外可用份额，不从现货、其他持仓、TRX、USDT 或储备自动补足。多个候选持仓必须指定来源，金额超限、在途操作、未归属利息、过期行情或读取期间资金快照变化均拒绝预览。读取源账本挂载为只读，使用最近六十秒内已对账快照，不构造交易所写客户端。预览按当前 USDGO 买一价投影追加本金与成本、按现有净值增发份额，并展示原信号条件下的买入预算及完整计息周期的归属检查点；所有变化仅在内存中计算。返回 `preview_id`、`preview_only=true` 和 `execution_enabled=false`，不保存可确认凭证，不供原正式并入接口直接确认。`/contribution-preview` 页面沿用原网站登录，提供定额筛选和前后对照；上线只需更换只读历史服务及热加载路由，交易进程无需重启。

正式定额确认由原交易服务的 `selected_contribution` 方法提供，接口为 `/api/v1/trx/live/contribution/selected/preview`、`confirm` 和 `status`。固定清单从账户账本目录内的 `selected-contribution-policy.local.json` 读取，仅适用于事先核对的账户、指定批次、定额 USDGO 和理财持仓；调用方不能扩大币种、数量或来源。该文件只包含已批准的账户绑定、账本及收益起点、原始本金、策略指纹与 `selection`，不允许覆盖账本或审阅目录；缺失或无效时拒绝操作。真实账户、金额及订单标识不写入源码。已有版本迁移时，须先在私有账户目录保存与原批准范围完全一致的清单，并核对策略指纹及批次策略哈希，不能从当前余额重新生成；文件权限设为 `0600`，不提交 Git。生成清单只保存私有审阅凭证；明确确认后，在原服务锁和策略运行锁内完成备份、执行账本锁及版本校验，再交给原 `live_contribution.apply` 原子记账并同步运行时。不得在外部进程直接写审阅字段，否则旧 worker 遇到账本锁竞争可能暂停。五分钟有效期、确认时报价漂移上限 1%、一次性批次标记和实际入账回执共同限制过期及重复提交；异常结果先查同批回执，不另建批次重试。页面要求用户核对并勾选后手动确认，原 TRX 成本、历史收益和收益起点保留。此功能的部署需升级原交易进程，须与仅升级只读服务的预览区分；部署状态以实际线上验收为准。

## 本地研究与实盘手续费口径

自2026-10-25起，本地策略回测统一以买入、卖出每边0.1%手续费为基准，运行计划显式使用 `buy_fee=0.001`、`sell_fee=0.001`，不得直接沿用账户快照中的VIP优惠费率。新账户此前的0.07%依赖VIP条件，资金减少可能恢复至0.1%；旧账户没有该VIP优惠，不能套用新账户费率。已冻结的0.07%研究结果保留原始口径，不能改标为0.1%，相关收益与参数建议须重算后再评估。

本地研究继续按50%手续费返佣、到账后复投计算：先按0.1%完整扣费，实际模拟到账时单列返佣收益并增加可部署资金，未到账部分不计收益和可用预算；不得直接用返佣后的0.05%代替成交扣费率。其余计息、申赎及返佣到账时间假设须在各研究计划中明确记录。

服务器实盘按各自账户API返回的实时适用费率进行预算与盈利卖出复核，并以实际成交回执的手续费金额及币种记账。`ClassicBroker.market` 查询账户 `trade-rate` 的 `takerFeeRate`，`LiveStrategy.environment` 更新引擎买卖费率；不得将本地0.1%研究假设或另一账户的VIP优惠费率固定写入实盘。读取失败或未验证的费率不能默认为优惠费率。本地研究口径调整不构成部署或修改运行中账户的授权。

## 启动、暂停和恢复

API 入口为 `trx-server --config <本地配置路径>`。登录 JWT 与独立监控、历史服务沿用相同的身份字段和 HS256 签名格式。现有实盘路径、账户 ID、冻结参数和 SQLite 格式保持不变。

默认仅允许已有账户，并关闭自动恢复。明确启用 `trx_phase1.auto_resume_live` 时必须同时启用 `existing_live_only`，只能恢复已绑定且原先期望运行的账户。不得同时运行第二个真实交易实例。

指标初始化需要连续、已关闭并完成确认的分钟数据及既有价格位置参考历史。仅初始化之后的新收盘能产生决策，离线期间的信号不追单。先核对已有执行和到账，再接受新增意图。暂停停止新增意图，已提交订单、到账、账本与持仓仍须核对。

交易进程与只读服务分离。更新只读页面或监控服务时，不应为了它们重启交易进程。

## USDGO 策略外理财储备

已有账户可通过鉴权的 `POST /api/v1/trx/live/reserve/half`，以固定 `allocation_id` 将划分时策略内 USDGO 的一半（向下保留八位小数）一次性划为策略外储备。必须已有完整首仓、处于空闲运行状态，且实际策略所属活期本金足以覆盖；不初始化账户，不发送兑换、申购、赎回或交易请求。提交前在线备份账本，提交后不得用旧备份覆盖仍在变化的实盘账本。

储备仍留在原活期持仓，只在内部变更归属。账本以本金划出调整可部署本金和基金份额，保持单位净值、既有交易利润、原始本金基准与 TRX 批次成本连续。普通交易预算、赎回计划和外部资产并入入口都排除储备；同一标识重试返回原记录，换标识也不能再次对半划分。

实际到账利息保留原凭证并按既有完整计息小时规则分摊，储备是策略外本金的子集，不能重复计入总权重。划分所在的不完整小时仍按原归属，下一完整计息小时开始采用新归属；不回写过去的派息。储备的到账利息默认单列为策略外现货，不进入策略预算。页面将其与策略总权益、策略利息分开展示。

经账户专项授权后，可启用 `external-usdgo-interest-reinvestment.json`。仅将已核实到账、已分摊且尚未使用的策略外 USDGO 利息，在满足当前产品最低申购额、精度和容量时，经原串行执行流程自动申购；原策略交易和理财动作优先。启用清单绑定账户、账本、持仓及资金归属基线，历史利息须逐笔列明，启用后的新增利息沿用原生分摊回执。新增人工资金归属变动会延后此功能并要求重新核对，不自动扩大来源范围。交易所业务单、资金流水、实际持仓及钱包余额全部核对通过后，原子更新策略外现货与理财位置，并按原利息回执记录消耗量以防重复复投；本金、份额、TRX 批次及策略利润不变。复投后的金额继续作为策略外计息权重，不参与 TRX 买卖。未知申购结果沿用原保护，不自动重复提交。

实盘信号卡片的波动率来自策略已保存的 `last_sigma` 与分钟确认时间。高波动的加档作用按当前快照解释目标档位；实际已排程买卖周期独立展示，不能把当前推算冒充过去调度的因果记录。图表卡片保留总览、权益与行情、持仓数量，另提供 TRX P75 和120分钟波动率视图。 已启用活跃区间的账户还可查看“高频区间价格带”：叠加已确认分钟收盘价、每日上下界及区间阴影，共用24小时／7天／全部时间范围。价格带由独立历史服务归档到自己的 `range-bands.sqlite`，不写交易账本；实盘归档来自优化策略启用后保存的区间；按相同规则离线回算的历史另存于 `reconstructed_range_bands`，与实盘记录分表、分色展示，不计入收益。新版图表通过 `include_history=true` 读取回算历史，旧客户端继续只读取实盘记录；缺失日期保留空白。

`live_history_app` 的鉴权只读 `GET /api/v1/trx/live/indicators` 从本账户已有 `live_candles` 重建历史指标。P75按北京时间每日生效、排除当天并要求完整回看窗口；小时等效波动率为过去120个分钟对数收益的总体标准差乘以√60。缺口留空、不补零、不下载行情、不写金融账本。每日P75不降采样；分钟展示采样保留分桶首尾、波动极值与缺失，按账户区分内存缓存。历史重建不是实际交易或调度记录。

## 请求预算与安全恢复

TRX 私有读取、公有行情和验收工具共享 `user_data/trx_phase1/request-limits.sqlite`。本地保守预算为每个已确认 UID 每秒 8 次私有请求、公有请求每秒 8 次，并跨进程平滑调度。赎回许可至少间隔 61 秒。预算数据库只保存哈希、时间和计数。

读取遇到 429 时发布共享冷却并有限重试；金融 POST 不自动重试。持久化意图先于网络发送。可证明未发送的请求与发送结果不明的请求分开恢复；取消订单也需保留原截止时间，终态与实际成交优先。

## 独立观察、通知与备份

`live_ops_app` 以只读方式挂载账户目录，不持有交易密钥，不构造交易 worker。它每 30 秒检查心跳、分钟确认、到账核对、漏判、未归属利息、备份、磁盘和内存。连续异常才告警，同一故障去重，恢复单独通知。

余额与到账流水短暂不同步时，执行端最多增加一次只读重取，所有币种仍须通过原有精确余额校验才能提交操作；无凭证差额不会计入收益或预算。已审核的 USDT 活期利息继续归策略外。等待期间保留核对码、起始时间及币种、实际值、预期值和差额；只有较晚一次完整余额校验通过，才清除旧等待标记，执行中的申购无需等到整个流程结束。监控将原有五分钟宽限内的账户证据等待展示为等待状态，超时、异常流水、执行错误及心跳过期仍按原保护升级告警或阻断。

首次启用监控只建立历史基线，不补发旧成交或虚构启动。后续启动、暂停和恢复在独立通知数据库内与 outbox 原子保存；通知区分变更确认时间与发送时的当前状态。Telegram 响应不明时保留待核对状态，不自动重发。通知不改变交易状态和金融账本。

独立监控配置包含 `source`、`account_id`、`state`、`backup_status`、`disk_path`、`username`、`jwt_secret_key`，可选 `notification_file` 和 `resource_file`。Telegram 文件使用 `enabled`、`bot_token`、`chat_id`，置于本地或服务器，权限 0600。 可配置 `source_label` 和 `source_domain`，所有告警、恢复、成交与策略状态通知统一加上 `【名称｜域名】` 前缀及网站入口。当前两账户分别为 `Max｜trx.octo-agent.com` 和 `齿轮｜trxqs.octo-agent.com`，共用机器人及接收会话；首次接入不补发启用前的历史状态通知。配置、凭证和备份均不提交 Git。

启用 `acknowledgement_enabled` 和随机 `callback_secret` 后，新 Telegram 通知附带账户范围内唯一编号及“确认收到”按钮；完整发送文案、消息编号和接收确认保存在独立 `ops.sqlite` 中。`/notifications` 使用网站登录，展示逐条通知及接收状态，并支持用户核对旧消息后手动确认。旧消息不会重发或伪造 Telegram 消息编号。确认只解除这条通知的接收待核对状态，保留原发送结果和实际告警，不操作交易、资金或收益账本。共用机器人仅注册一个 HTTPS webhook，接收 `callback_query`，校验 secret、账户、私聊接收人、通知令牌及原始消息；不启动独立轮询抢占其他服务更新。

共用机器人的回调入口位于新账户监控服务。`callback_receiver_enabled` 可先开启接收，再启用 `acknowledgement_enabled` 发送按钮；`callback_peers` 按账户命名空间把旧账户的回调转给原 HTTPS 接口，旧服务代码和配置无需变更。转发只允许固定旧域名和路径，禁用重定向；原接收器不可达时返回 503，由 Telegram 重试，不能在新账户误记确认。上游 webhook 切换保留待处理更新，失败时恢复原地址和 secret。

`live_backup` 使用 SQLite online backup API，只读打开源账本，校验账户、版本、完整性和归档校验和；不覆盖源目录，不调用交易执行。自动保留最近与按日代表快照，并受总量预算限制；服务器内备份不等于异地备份。恢复工具需单独提供凭证并核对账户，不能用空账户代替已有账本。

`live_history_app` 提供独立、鉴权的只读历史接口。`live_resources` 可由宿主机定时采集交易容器资源，监控服务只读消费结果，不挂载 Docker socket。内存、磁盘和备份告警只通知，不自动暂停、重启或操作资金。

## 测试资料

当前引擎、实盘与通知测试使用模拟行情和临时账户。历史 `test_price_event_research` 与 `test_sell_confirmation_research` 需要本机原始实验包；没有这些归档时跳过，不伪造历史证据。账户、历史行情、研究结果及部署证据保留在本地忽略目录，不随源码发布。
