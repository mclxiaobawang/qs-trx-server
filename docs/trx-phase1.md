# TRX 策略与运维说明

## 保留的功能

`freqtrade/strategy/trx_phase1` 是策略与账户逻辑，`freqtrade/rpc/api_server/api_trx.py` 提供专用 HTTP API。实盘、历史研究和虚拟执行共享决策引擎与批次账本。原 Freqtrade 原生策略适配器及其钱包已移除；实盘使用独立 `LiveService` / `LiveExecution` 流程。

- 策略：一分钟基础时钟、动态确认周期、价格位置、信号过期和执行前复核。
- 账本：Decimal 本金批次、实际手续费、部分成交、成本与已实现利润、独立留存利息。
- 研究：历史回放、参数对照、分段与跨期研究、逐笔诊断、风险和资金准备分析。
- 实盘：Bitget Classic 交易、理财申赎及到账核对、收入归属、账户增资与重启恢复。
- 运维：只读快照、历史曲线、独立告警与 Telegram 成交/生命周期通知、在线备份和资源采集。

## 策略和资金约束

一分钟收盘之后才形成决策；确认后的下一分钟才允许回放成交。UTC 边界定义长周期，波动率来自过去一分钟对数收益率。参数、周期和公共本金锚点在下一次评估之前冻结；一次确认最多形成一个待执行计划，执行前复核只能取消或缩减，不能临时创造信号。

公共本金锚点在第一次执行前固定，执行完成后按真实决策 VWAP 更新，本金归零后保留。利息、理财和币种兑换不改变锚点。实际成交及亏损如实记账；卖出分配只选择满足门槛的本金批次，优先较新的合格批次，留存利息不参加普通卖出。

账本 SQLite 使用版本校验和原子状态更新。重复成交与到账回执按其真实 ID 去重。未知金融请求不自动重发，应通过读取订单与回执核对。研究默认资金和收益率是假设，不构成实盘账户配置或已验证收益。

## 启动、暂停和恢复

API 入口为 `trx-server --config <本地配置路径>`。登录 JWT 与独立监控、历史服务沿用相同的身份字段和 HS256 签名格式。现有实盘路径、账户 ID、冻结参数和 SQLite 格式保持不变。

默认仅允许已有账户，并关闭自动恢复。明确启用 `trx_phase1.auto_resume_live` 时必须同时启用 `existing_live_only`，只能恢复已绑定且原先期望运行的账户。不得同时运行第二个真实交易实例。

指标初始化需要连续、已关闭并完成确认的分钟数据及既有价格位置参考历史。仅初始化之后的新收盘能产生决策，离线期间的信号不追单。先核对已有执行和到账，再接受新增意图。暂停停止新增意图，已提交订单、到账、账本与持仓仍须核对。

交易进程与只读服务分离。更新只读页面或监控服务时，不应为了它们重启交易进程。

## 请求预算与安全恢复

TRX 私有读取、公有行情和验收工具共享 `user_data/trx_phase1/request-limits.sqlite`。本地保守预算为每个已确认 UID 每秒 8 次私有请求、公有请求每秒 8 次，并跨进程平滑调度。赎回许可至少间隔 61 秒。预算数据库只保存哈希、时间和计数。

读取遇到 429 时发布共享冷却并有限重试；金融 POST 不自动重试。持久化意图先于网络发送。可证明未发送的请求与发送结果不明的请求分开恢复；取消订单也需保留原截止时间，终态与实际成交优先。

## 独立观察、通知与备份

`live_ops_app` 以只读方式挂载账户目录，不持有交易密钥，不构造交易 worker。它每 30 秒检查心跳、分钟确认、到账核对、漏判、未归属利息、备份、磁盘和内存。连续异常才告警，同一故障去重，恢复单独通知。

首次启用监控只建立历史基线，不补发旧成交或虚构启动。后续启动、暂停和恢复在独立通知数据库内与 outbox 原子保存；通知区分变更确认时间与发送时的当前状态。Telegram 响应不明时保留待核对状态，不自动重发。通知不改变交易状态和金融账本。

独立监控配置包含 `source`、`account_id`、`state`、`backup_status`、`disk_path`、`username`、`jwt_secret_key`，可选 `notification_file` 和 `resource_file`。Telegram 文件使用 `enabled`、`bot_token`、`chat_id`，置于本地或服务器，权限 0600。配置、凭证和备份均不提交 Git。

`live_backup` 使用 SQLite online backup API，只读打开源账本，校验账户、版本、完整性和归档校验和；不覆盖源目录，不调用交易执行。自动保留最近与按日代表快照，并受总量预算限制；服务器内备份不等于异地备份。恢复工具需单独提供凭证并核对账户，不能用空账户代替已有账本。

`live_history_app` 提供独立、鉴权的只读历史接口。`live_resources` 可由宿主机定时采集交易容器资源，监控服务只读消费结果，不挂载 Docker socket。内存、磁盘和备份告警只通知，不自动暂停、重启或操作资金。

## 测试资料

当前引擎、实盘与通知测试使用模拟行情和临时账户。历史 `test_price_event_research` 与 `test_sell_confirmation_research` 需要本机原始实验包；没有这些归档时跳过，不伪造历史证据。账户、历史行情、研究结果及部署证据保留在本地忽略目录，不随源码发布。
